========================================================================

AidFlow uses queues + workers + redis + async jobs, so multiple processes run.

AidFlow now has 2 types of processes

1. API Server (Express app)

Handles:

login
create donation
create campaign
wallet spend
fetch data

Run with: npm run dev


2. Workers (background processors)

Handle heavy tasks:

AI decision
fraud detection
blockchain anchoring
donation risk scoring
wallet expiry
recurring donations

Run with: npm run workers  
{"workers": "nodemon src/workers/index.js" in package.json}



WHY WORKERS ARE NEEDED

Example:
User donates ₹5000

System must:

store donation
call AI risk model
calculate fraud probability
write audit log
maybe anchor blockchain

If API waits → response slow 
So we do:

API: save donation → send job to queue → return response fast

Worker: process AI + fraud in background


Visual Flow:-

User clicks donate
        ↓
Express API (npm run dev)
        ↓
job added to Redis queue
        ↓
Worker picks job (npm run workers)
        ↓
AI decision / fraud check
        ↓
DB updated


WHAT EACH COMPONENT DOES:-

EXPRESS SERVER:

Command: npm run dev

Starts:

app.js
routes
controllers
services
middleware
swagger docs
queue dashboard UI

Test: http://localhost:5000/health


REDIS SERVER:

Queue storage.
BullMQ stores jobs here.

Start once:

Linux: sudo service redis-server start

OR

redis-server

Check: redis-cli ping

should return: PONG


WORKERS:

Command: npm run workers

Runs:

ai.worker
donation.worker
fraud.worker
blockchain.worker
walletExpiry.worker
recurring.worker

Workers continuously watch queue.


QUEUES:

Queues live in Redis.

Example:

ai-processing queue
donation-processing queue
fraud-detection queue
blockchain-anchor queue

Visible in dashboard: http://localhost:5000/admin/queues


SWAGGER DOCS:

API documentation UI.

Open: http://localhost:5000/docs

Lets you test APIs easily.
